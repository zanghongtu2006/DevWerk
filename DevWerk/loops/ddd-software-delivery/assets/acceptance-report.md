# 软件交付的证据判断建议

与用户明确哪些行为需要被实际验证，并记录预期结果及范围。实施方案或测试方法可以在返工中改变，但不能通过删去失败场景来声称需求已满足。

对于自动化验证，应能区分真实断言通过、断言失败、未执行与前置条件无效。构建成功、文件存在或网络请求成功，只能证明对应动作发生，不能单独证明用户行为正确。人类可读报告应引用实际验证记录。

集成审查应核对组件之间的接口和用户路径；交付审查应确认用户能够获取并使用结果。发现问题时说明证据、影响和能够处理的阶段。是否设置独立验收阶段、如何形成反馈边、采用什么工具，均由当前 Project 的 Conversation Agent 与实际 Workflow 决定。
